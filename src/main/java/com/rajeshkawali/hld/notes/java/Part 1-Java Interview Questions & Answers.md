# SECTION 1 — JAVA BASICS

## Q1. What is Java?

### Interview Answer

Java is a high-level, object-oriented, class-based programming language designed to be platform independent.

Java follows the principle:

"Write Once, Run Anywhere."

Java source code is compiled into bytecode, and the bytecode runs on the JVM.

### Flow

Java source code
      |
      v
javac compiler
      |
      v
Bytecode (.class)
      |
      v
JVM
      |
      v
Machine code

### Example

public class HelloWorld {

    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}

### Important point

Java is platform independent because the same bytecode can run on different operating systems as long as a compatible JVM is available.

---

# Q2. Why is Java platform independent?

### Interview Answer

Java is platform independent because Java source code is compiled into platform-independent bytecode, which is executed by a platform-specific JVM.

For example:

Windows JVM
Linux JVM
Mac JVM

can all execute the same Java bytecode.

### Important distinction

Java is:

    Platform Independent

    Platform Dependent

# SECTION 3 — OOP

# Q15. What are the four pillars of OOP?

The four commonly cited pillars are:

1. Encapsulation
2. Inheritance
3. Polymorphism
4. Abstraction

---

# Q16. What is encapsulation?

> **Encapsulation is the process of hiding an object's internal data and providing controlled access to it through methods. In Java, it is commonly achieved using private fields and public methods such as getters and setters.**


Encapsulation means bundling data and behavior together and controlling access to internal state.
Example:

class BankAccount {

    private double balance;

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {

        if (amount > 0) {
            balance += amount;
        }
    }
}

Here:

balance

is private.

External code cannot directly modify it.

This allows the class to control how its state changes.

---

# Q17. What is abstraction?

> **Abstraction means hiding implementation details and exposing only the required functionality. In Java, abstraction is mainly achieved using abstract classes and interfaces.**

Abstraction means exposing essential behavior while hiding implementation details.

Example:

interface PaymentService {

    void pay(double amount);
}

Implementation:

class CreditCardPayment implements PaymentService {

    @Override
    public void pay(double amount) {
        System.out.println("Processing credit card payment");
    }
}

The caller only needs to know:

pay()

It doesn't need to know the internal payment processing details.

---

# Q18. What is inheritance?

> **Inheritance is a mechanism where a child class acquires properties and methods of a parent class. In Java, it is achieved using the extends keyword and promotes code reuse.**

Inheritance allows one class to acquire properties and behavior from another class.

Example:

class Animal {

    void eat() {
        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Barking");
    }
}

Dog inherits:

eat()

from Animal.

---

# Q19. What is polymorphism?

> **Polymorphism means one interface or method name can have multiple forms. In Java, method overloading provides compile-time polymorphism, while method overriding provides runtime polymorphism.**

Polymorphism means:

"One interface/reference, multiple implementations."

Two major types:

1. Compile-time polymorphism
2. Runtime polymorphism

---

# Q20. What is method overloading?

Method overloading means having multiple methods with the same name but different parameter lists.

Example:

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}

This is compile-time polymorphism.

---

# Q21. What is method overriding?

A subclass provides its own implementation of a superclass method.

Example:

class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Bark");
    }
}

Animal animal = new Dog();

animal.sound();

Output:

Bark

The actual object's implementation is selected at runtime.

---

# Q22. Overloading vs overriding?

| Overloading | Overriding |
|---|---|
| Same class usually | Parent-child relationship |
| Same method name | Same method signature |
| Different parameters | Same parameters |
| Compile time | Runtime |
| Return type alone cannot overload | Covariant return type allowed |

Remember:

**What is method overloading?**
Method overloading means defining multiple methods with the same name but different parameter lists. 
It is compile-time polymorphism.

**What is method overriding?**
Method overriding occurs when a child class provides its own implementation of an inherited instance method with the same signature. 
It enables runtime polymorphism.

---

# Q23. Can we overload by changing only return type?

No.

This is invalid:

int calculate() {
    return 10;
}

double calculate() {
    return 10.0;
}

The parameter list is identical.

Return type alone cannot distinguish overloaded methods.

---

# Q24. Can static methods be overridden?

No.

Static methods belong to the class rather than an object.

If a subclass defines a static method with the same signature, it is method hiding, not overriding.

Example:

class Parent {

    static void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    static void display() {
        System.out.println("Child");
    }
}

Parent p = new Child();

p.display();

Output:

Parent

Because static method resolution is based on reference type.

---

# Q25. Can private methods be overridden?

No.

Private methods are not visible to subclasses, so they cannot be overridden.

---

# Q26. Can final methods be overridden?

No.

final method means:

> This method cannot be overridden by subclasses.

Example:

class Parent {

    final void display() {
        System.out.println("Hello");
    }
}

Child cannot override display().

---

# SECTION 4 — CLASS, OBJECT, CONSTRUCTOR

# Q27. What is a class?

A class is a blueprint/template for creating objects.

Example:

class Employee {

    String name;

    void work() {
        System.out.println("Working");
    }
}

---

# Q28. What is an object?

An object is an instance of a class.

Example:

Employee employee = new Employee();

Here:

Employee -> class

employee -> reference

new Employee() -> object

---

# Q29. What is a constructor?

A constructor initializes an object when it is created.

Example:

class Employee {

    private String name;

    Employee(String name) {
        this.name = name;
    }
}

Usage:

Employee e = new Employee("John");

---

# Q30. What are constructor rules?

Important rules:

1. Constructor name must match class name.
2. Constructor has no return type.
3. Constructors can be overloaded.
4. Constructors are not inherited.
5. Constructor can have access modifiers.
6. Constructor can call another constructor using this().
7. Constructor can call parent constructor using super().

---

# Q31. What is this?

this refers to the current object.

Example:

class Employee {

    private String name;

    Employee(String name) {
        this.name = name;
    }
}

Here:

this.name

means the instance variable.

name

means the constructor parameter.

---

# Q32. What is super?

super refers to the parent class.

Example:

class Parent {

    String name = "Parent";
}

class Child extends Parent {

    String name = "Child";

    void print() {
        System.out.println(super.name);
    }
}

Output:

Parent

super can also call a parent constructor:

super();

---

# Q33. Difference between this() and super()?

this():

Calls another constructor in the same class.

super():

Calls a constructor in the parent class.

Example:

class Employee {

    Employee() {
        this("Unknown");
    }

    Employee(String name) {
        System.out.println(name);
    }
}

Parent example:

class Child extends Parent {

    Child() {
        super();
    }
}

Important:

this() or super() must be the first statement in a constructor.

**this()** calls another constructor of the same class, 
while **super()** calls the constructor of the parent class. 
Both must be the first statement in a constructor; 
**this()** is mainly used for constructor chaining, 
while **super()** is used for parent-class initialization.

protected:

Accessible within the same package and to subclasses, with important rules when accessed from another package.

# SECTION 6 — STATIC, FINAL

# Q37. What is static?

static means the member belongs to the class rather than individual objects.

Example:

class Employee {

    static String company = "ABC";
}

All Employee objects can share the same company field.

---

# Q38. What is a static variable?

A static variable has one class-level copy.

Example:

class Employee {

    static int employeeCount = 0;

    Employee() {
        employeeCount++;
    }
}

Employee e1 = new Employee();
Employee e2 = new Employee();

System.out.println(Employee.employeeCount);

Output:

2

---

# Q39. What is a static method?

A static method belongs to the class.

Example:

class MathUtil {

    static int square(int n) {
        return n * n;
    }
}

Usage:

int result = MathUtil.square(5);

---

# Q40. Why can't a static method directly access instance variables?

Because static methods belong to the class and don't automatically have an object reference.

Example:

class Test {

    int value = 10;

    static void display() {

        // System.out.println(value); // compile error
    }
}

You need an object:

Test t = new Test();

System.out.println(t.value);

---

# Q41. What is final?

final means something cannot be changed in the relevant context.

final variable:

Cannot be reassigned.

final method:

Cannot be overridden.

final class:

Cannot be extended.

---

# Q42. Can a final object be modified?

Yes.

This is a very common interview trap.

Example:

final List<String> names = new ArrayList<>();

names.add("John");

This is allowed.

But:

names = new ArrayList<>();

is not allowed.

final prevents reassignment of the reference.

It does not automatically make the object immutable.

---

# Q43. final vs finally vs finalize?

final:

Keyword used for variables, methods and classes.

finally:

Block used with exception handling.

finalize():

Old Object method historically associated with GC cleanup; it has been deprecated for removal and should not be used for resource management.

Modern Java code should use:

- try-with-resources
- AutoCloseable
- explicit resource management

# SECTION 7 — STRING

# Q44. Why is String immutable?

Once a String object is created, its content cannot be changed.

Example:

String s = "Java";

s.concat(" Programming");

The original String remains unchanged because String operations produce new strings.

Correct:

s = s.concat(" Programming");

---

# Q45. Why is String immutable?

Common reasons:

1. Security
2. Thread safety
3. String pool optimization
4. Hash code caching
5. Safe use as HashMap keys
6. Class loading/security-related use cases

Example:

String username = "admin";

If String were mutable, many parts of the application could unexpectedly change the same shared String value.

---

# Q46. What is String pool?

Java maintains a pool of interned String literals.

Example:

String a = "Java";
String b = "Java";

Both may refer to the same pooled String object.

Therefore:

a == b

is true for these literals.

But:

String c = new String("Java");

c == a

is false because new String creates another object.

Yet:

c.equals(a)

is true.

---

# Q47. == vs equals() for String?

Example:

String a = new String("Java");
String b = new String("Java");

a == b

false

a.equals(b)

true

Remember:

== -> reference comparison

equals() -> content/logical comparison

---

# Q48. String vs StringBuilder vs StringBuffer?

String:

Immutable.

StringBuilder:

Mutable and generally preferred for single-threaded string construction.

StringBuffer:

Mutable and synchronized; generally slower than StringBuilder when synchronization isn't needed.

Example:

StringBuilder builder = new StringBuilder();

builder.append("Hello");
builder.append(" ");
builder.append("Java");

System.out.println(builder);

---

# Q49. Why is StringBuilder faster than String concatenation in loops?

Bad approach:

String result = "";

for (int i = 0; i < 1000; i++) {
    result += i;
}

Repeated concatenation can create many intermediate String objects.

Better:

StringBuilder result = new StringBuilder();

for (int i = 0; i < 1000; i++) {
    result.append(i);
}

---

# SECTION 8 — EQUALS, HASHCODE, TOSTRING

# Q50. Why override equals()?

Object.equals() provides default identity-based equality.

If business logic requires logical equality, override it.

Example:

Employee e1 = new Employee(101L);
Employee e2 = new Employee(101L);

If employee ID defines identity:

e1.equals(e2)

should be true.

---

# Q51. Why override hashCode()?

Because HashMap and HashSet use hashCode() as part of their lookup process.

Important rule:

If:

a.equals(b)

is true, then:

a.hashCode() == b.hashCode()

must be true.

---

# Q52. Why override toString()?

For useful debugging and logging.

Default:

Employee@5e2de80c

Custom:

Employee{id=101, name='John'}

---

# Q53. Write equals(), hashCode() and toString()

Example:

import java.util.Objects;

class Employee {

    private Long id;
    private String name;

    @Override
    public boolean equals(Object o) {

        if (this == o) {
            return true;
        }

        if (!(o instanceof Employee)) {
            return false;
        }

        Employee other = (Employee) o;

        return Objects.equals(id, other.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }

    @Override
    public String toString() {
        return "Employee{" +
                "id=" + id +
                ", name='" + name + '\'' +
                '}';
    }
}

---

# Q54. What is the equals/hashCode contract?

Answer:

If:

a.equals(b) == true

then:

a.hashCode() == b.hashCode()

must be true.

But:

a.hashCode() == b.hashCode()

does not imply:

a.equals(b) == true.

Different objects can have hash collisions.

---

# Q55. What are the equals() contract rules?

equals() should be:

1. Reflexive
2. Symmetric
3. Transitive
4. Consistent
5. False for null

Example:

a.equals(a)

must be true.

If:

a.equals(b)

is true, then:

b.equals(a)

must be true.

---

# SECTION 9 — COLLECTIONS

# Q56. What is the Java Collection Framework?

It is a set of interfaces and classes for storing and manipulating groups of objects.

Important interfaces:

Collection
List
Set
Queue
Deque
Map

Map is part of the collections framework but does not extend Collection.

---

# Q57. Difference between List, Set and Map?

List:

- Ordered
- Allows duplicates
- Index-based access

Set:

- Does not allow duplicate elements according to its equality semantics

Map:

- Stores key-value pairs
- Keys are unique according to the map's key equality semantics

Examples:

List -> ArrayList

Set -> HashSet

Map -> HashMap

---

# Q58. ArrayList vs LinkedList?

ArrayList:

- Backed by a resizable array
- Fast random access
- Usually preferred for general-purpose list usage
- Insertion/removal in the middle can require shifting elements

LinkedList:

- Doubly linked structure
- Poor random access
- Can be useful for certain deque operations
- Often not the best default choice for list workloads

Interview answer:

> "ArrayList is generally the default choice unless I have a specific reason to use LinkedList."

---

# Q59. How does ArrayList work internally?

Conceptually, ArrayList uses a dynamically resized array.

Example:

ArrayList<Integer> list = new ArrayList<>();

list.add(10);
list.add(20);
list.add(30);

Internally:

```
[10][20][30][ ][ ]
```

When capacity is insufficient, it creates a larger array and copies elements.

Important:

ArrayList size and capacity are different concepts.

---

# Q60. ArrayList initial capacity?

If you know approximately how many elements you'll add, you can provide an initial capacity:

List<Integer> numbers = new ArrayList<>(1000);

This can reduce repeated resizing.

---

# Q61. What is HashSet?

HashSet stores unique elements.

Example:

Set<String> names = new HashSet<>();

names.add("John");
names.add("John");
names.add("Mary");

Only two logical elements remain.

HashSet relies on hashCode() and equals().

---

# Q62. What is TreeSet?

TreeSet stores elements in sorted order according to natural ordering or a Comparator.

Example:

Set<Integer> numbers = new TreeSet<>();

numbers.add(30);
numbers.add(10);
numbers.add(20);

Result:

[10, 20, 30]

---

# Q63. HashSet vs TreeSet?

HashSet:

- Hash-based
- No sorted-order guarantee
- Average O(1) basic operations under normal assumptions

TreeSet:

- Tree-based
- Sorted
- Basic operations generally O(log n)

Use TreeSet when sorted set behavior is required.

---

# Q64. What is LinkedHashSet?

LinkedHashSet maintains insertion order while providing set semantics.

Example:

Set<String> names = new LinkedHashSet<>();

names.add("John");
names.add("Mary");
names.add("David");

Iteration order:

John
Mary
David

---

# Q65. HashMap vs Hashtable?

HashMap:

- Not synchronized
- Allows one null key
- Allows null values
- Generally preferred in modern code when external synchronization isn't required

Hashtable:

- Legacy
- Synchronized
- Does not allow null keys or values

For concurrent access, modern code generally uses classes from java.util.concurrent rather than Hashtable.

---

# Q66. HashMap vs ConcurrentHashMap?

HashMap:

Not designed for concurrent mutation by multiple threads.

ConcurrentHashMap:

Designed for concurrent access.

It provides thread-safe operations with better concurrency characteristics than synchronizing an entire map in many use cases.

Important:

ConcurrentHashMap does not allow null keys or null values.

---

# Q67. How does HashMap work internally?

Simplified:

map.put(key, value)

    |
    v
key.hashCode()
    |
    v
calculate bucket
    |
    v
find bucket
    |
    v
compare keys using equals()
    |
    v
insert/update

For get():

map.get(key)

    |
    v
hashCode()
    |
    v
bucket
    |
    v
equals()
    |
    v
value

Modern HashMap implementations can use tree structures in heavily-collided buckets under certain conditions.

---

# Q68. Why does HashMap need both hashCode() and equals()?

hashCode():

Helps find the candidate bucket efficiently.

equals():

Determines whether the key is actually equal.

Remember:

hashCode -> narrowing search

equals -> exact equality

---

# Q69. Can HashMap have duplicate keys?

No.

If you do:

Map<Integer, String> map = new HashMap<>();

map.put(1, "A");
map.put(1, "B");

The second put replaces the value associated with key 1.

Result:

1 -> B

---

# Q70. Can HashMap have duplicate values?

Yes.

Example:

map.put(1, "A");
map.put(2, "A");

This is valid.

Keys must be unique according to the map's equality semantics.

Values do not have to be unique.

---

# Q71. What happens if a mutable object is used as a HashMap key?

Potentially dangerous.

Example:

Employee employee = new Employee(101L);

Map<Employee, String> map = new HashMap<>();

map.put(employee, "Developer");

employee.setId(999L);

Now hashCode() may change.

A later:

map.get(employee)

may fail unexpectedly.

Therefore:

> Keys should ideally be immutable with respect to fields used in equals() and hashCode().

# SECTION 10 — IMMUTABILITY

# Q72. What is an immutable object?

An immutable object cannot change its observable state after creation.

String is a classic example.

Example:

String s = "Java";

s.concat(" 17");

The original String remains unchanged.

---

# Q73. How do you create an immutable class?

Common approach:

1. Make class final.
2. Make fields private.
3. Make fields final.
4. Initialize fields through constructor.
5. Do not provide setters.
6. Return defensive copies for mutable objects.
7. Don't expose internal mutable state.

Example:

```
public final class Employee {

    private final String id;
    private final String name;

    public Employee(String id, String name) {
        this.id = id;
        this.name = name;
    }

    public String getId() {
        return id;
    }

    public String getName() {
        return name;
    }
}
```
---

# Q74. Why make an immutable class final?

If the class isn't final, a subclass could introduce mutable state or override methods in ways that break the intended immutability.

Making the class final prevents subclassing.

---

# Q75. What is defensive copying?

Suppose:

```
class Employee {

    private final List<String> skills;

    Employee(List<String> skills) {
        this.skills = new ArrayList<>(skills);
    }
}
```
The constructor copies the caller's list.

Otherwise:

List<String> skills = new ArrayList<>();

Employee e = new Employee(skills);

skills.add("Java");

could unexpectedly modify the Employee's internal state if the original list reference was stored directly.

---

# Q76. Is final enough to make an object immutable?

No.

Example:

final List<String> list = new ArrayList<>();

list.add("Java");

The reference cannot point to another list, but the list itself is still mutable.

final reference != immutable object

---

# SECTION 11 — EXCEPTION HANDLING

# Q77. What is an exception?

An exception is an event that disrupts the normal flow of program execution.

Example:

int result = 10 / 0;

This causes:

ArithmeticException

---

# Q78. Checked vs unchecked exceptions?

Checked exceptions:

Compiler requires them to be handled or declared.

Examples:

IOException
SQLException

Unchecked exceptions:

RuntimeException and its subclasses.

Examples:

NullPointerException
IllegalArgumentException
IndexOutOfBoundsException

---

# Q79. Error vs Exception?

Exception:

Usually represents conditions an application may reasonably handle.

Error:

Usually indicates serious JVM/system-level problems.

Examples:

Exception:

IOException

Error:

OutOfMemoryError
StackOverflowError

Generally, applications should not try to routinely recover from serious Errors.

---

# Q80. What is try-catch-finally?

Example:

try {
    int result = 10 / 0;
}
catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
}
finally {
    System.out.println("Cleanup");
}

finally normally executes whether an exception occurs or not, except in unusual termination situations such as JVM termination.

---

# Q81. Can finally block be skipped?

Yes, in abnormal JVM/process termination scenarios.

Example:

System.exit(0);

can terminate the JVM before finally executes.

Other catastrophic conditions can also prevent normal execution.

---

# Q82. Can we have try without catch?

Yes, if there is a finally block.

Example:

try {
    System.out.println("Hello");
}
finally {
    System.out.println("Cleanup");
}

---

# Q83. Can we have catch without try?

No.

catch must be associated with a try.

---

# Q84. Can we have multiple catch blocks?

Yes.

Example:

try {
    // code
}
catch (ArithmeticException e) {
    // handle
}
catch (RuntimeException e) {
    // handle
}

More specific exceptions should come before broader exceptions.

This is invalid:

catch (Exception e) {
}

catch (ArithmeticException e) {
}

because ArithmeticException is already covered by Exception.

---

# Q85. throw vs throws?

throw:

Used to explicitly throw an exception.

Example:

throw new IllegalArgumentException("Invalid age");

throws:

Declares that a method may throw specified checked exceptions.

Example:

void readFile() throws IOException {
}

Easy memory trick:

throw -> actually throws

throws -> declares possibility

---

# Q86. Can we throw checked exceptions from a method?

Yes, but the method must either:

1. Catch the exception, or
2. Declare it with throws.

Example:

void read() throws IOException {
    throw new IOException();
}

---

# Q87. What is try-with-resources?

It automatically closes resources implementing AutoCloseable.

Example:

```
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {

    String line = reader.readLine();
}
```

The reader is automatically closed.

This is preferred over manual close logic for resources that implement AutoCloseable.

---

# Q88. What is exception propagation?

If a method doesn't handle an exception, it can propagate up the call stack.

Example:

methodA()
   |
   v
methodB()
   |
   v
methodC()
   |
   v
exception

If methodC doesn't handle it, methodB may receive it.

If methodB doesn't handle it, methodA may receive it.

Eventually it may reach the JVM's uncaught exception handler.

---

# SECTION 12 — JAVA MEMORY

# Q89. Stack vs Heap?

Stack:

Usually contains:

- Method call frames
- Local variables
- References associated with stack frames

Heap:

Contains objects and arrays.

Example:

Employee employee = new Employee();

Conceptually:

Stack:
employee reference

Heap:
Employee object

The exact JVM implementation details are more nuanced, but this is the standard interview model.

---

# Q90. What is garbage collection?

Garbage collection automatically identifies objects that are no longer reachable and reclaims their memory.

Example:

Employee e = new Employee();

e = null;

If there are no other reachable references to that Employee object, it becomes eligible for garbage collection.

Important:

Eligible for GC does not mean immediately collected.

---

# Q91. Can we force garbage collection?

No.

You can request it:

System.gc();

but the JVM is not required to perform GC immediately because of that call.

Interview answer:

> "System.gc() is only a request or hint to the JVM, not a guarantee."

---

# Q92. What is a memory leak in Java?

Java has automatic garbage collection, but memory leaks can still happen.

A memory leak occurs when objects are no longer logically needed but remain reachable.

Example:

static List<Object> cache = new ArrayList<>();

If objects are continuously added and never removed, they remain reachable through the static collection.

Therefore GC cannot reclaim them.

---

# Q93. What is OutOfMemoryError?

It occurs when the JVM cannot allocate required memory.

Common causes:

- Excessive object creation
- Unbounded collections
- Memory leaks
- Very large arrays
- Inappropriate heap sizing

---

# Q94. What is StackOverflowError?

Usually occurs when the call stack grows too deeply.

Classic example:

static void test() {
    test();
}

test();

This causes infinite recursion until stack space is exhausted.

---

# SECTION 13 — JAVA 8+

# Q95. What is a lambda expression?

A lambda is a concise way to represent behavior/function.

Example:

List<String> names = List.of("John", "Mary", "David");

names.forEach(name -> System.out.println(name));

Instead of writing an anonymous class.

---

# Q96. What is a functional interface?

An interface with exactly one abstract method.

Examples:

Runnable
Callable
Comparator
Predicate
Function
Consumer
Supplier

Example:

@FunctionalInterface
interface Calculator {

    int calculate(int a, int b);
}

Usage:

Calculator add = (a, b) -> a + b;

---

# Q97. What is @FunctionalInterface?

It tells the compiler that the interface is intended to have exactly one abstract method.

Example:

@FunctionalInterface
interface Printer {

    void print();
}

If you add another abstract method, compilation fails.

Default and static interface methods do not count as abstract methods.

---

# Q98. What is Stream API?

Stream API provides a declarative way to process collections and other data sources.

Example:

List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

List<Integer> result =
        numbers.stream()
               .filter(n -> n % 2 == 0)
               .map(n -> n * 10)
               .toList();

Result:

[20, 40, 60]

---

# Q99. Intermediate vs terminal stream operations?

Intermediate operations:

- filter()
- map()
- sorted()
- distinct()
- limit()
- skip()

They return another Stream and are generally lazy.

Terminal operations:

- collect()
- toList()
- forEach()
- reduce()
- count()
- anyMatch()

They trigger stream processing.

Example:

numbers.stream()
       .filter(n -> n > 10)
       .map(n -> n * 2)
       .toList();

filter and map:

Intermediate

toList:

Terminal

---

# Q100. What does lazy evaluation mean in streams?

Intermediate operations are not normally executed immediately.

Example:

numbers.stream()
       .filter(n -> {
           System.out.println(n);
           return n > 5;
       });

Nothing necessarily executes until a terminal operation is invoked.

Add:

.toList();

and processing begins.

---

# Q101. map() vs flatMap()?

map():

One input -> one output.

Example:

List<String> names = List.of("John", "Mary");

List<Integer> lengths =
        names.stream()
             .map(String::length)
             .toList();

flatMap():

One input -> multiple outputs, then flattens them.

Example:

List<List<Integer>> numbers =
        List.of(
            List.of(1, 2),
            List.of(3, 4)
        );

List<Integer> result =
        numbers.stream()
               .flatMap(List::stream)
               .toList();

Result:

[1, 2, 3, 4]

---

# Q102. filter() vs map()?

filter():

Selects elements.

Example:

numbers.stream()
       .filter(n -> n > 10)

map():

Transforms elements.

Example:

numbers.stream()
       .map(n -> n * 2)

Easy memory:

filter -> keep/remove

map -> transform

---

# Q103. What is Optional?

Optional is a container that may or may not contain a value.

Example:

Optional<String> name = Optional.of("John");

Optional<String> empty = Optional.empty();

It can make absence explicit and reduce some accidental null handling.

---

# Q104. Optional.of() vs ofNullable()?

Optional.of(value):

Value must not be null.

Optional.ofNullable(value):

Accepts null and produces Optional.empty() when value is null.

Example:

Optional<String> a = Optional.of("Java");

Optional<String> b = Optional.ofNullable(null);

b.isEmpty() -> true

This would throw:

Optional.of(null);

---

# Q105. What is method reference?

Method reference is a shorter form of certain lambdas.

Lambda:

names.forEach(name -> System.out.println(name));

Method reference:

names.forEach(System.out::println);

---

# Q106. What are default methods in interfaces?

Java allows interfaces to contain default implementations.

Example:

```
interface Vehicle {

    default void start() {
        System.out.println("Starting");
    }
}
```
A class implementing Vehicle automatically gets the default method unless it overrides it.

---

# Q107. Why were default methods introduced?

One major reason was allowing interfaces to evolve without breaking all existing implementations.

For example, a new default method can be added without requiring every existing implementing class to immediately implement it.

---

# Q108. Can interfaces have static methods?

Yes.

Example:

```
interface Utility {

    static void print() {
        System.out.println("Hello");
    }
}
```
Call:

Utility.print();

Static interface methods are not inherited as instance methods by implementing classes.

# Q113. Comparable vs Comparator?

# SECTION 16 — ADVANCED COLLECTION QUESTIONS

# Q123. What is fail-fast behavior?

Some collection iterators detect structural modification during iteration and throw ConcurrentModificationException.

Example:

```
List<String> names =
        new ArrayList<>(List.of("A", "B", "C"));

for (String name : names) {

    if (name.equals("B")) {
        names.remove(name);
    }
}
```
This can cause:

ConcurrentModificationException

Use an Iterator's remove() or another appropriate approach.

---

# Q124. How do you safely remove elements while iterating?

Using Iterator:

```
Iterator<String> iterator = names.iterator();

while (iterator.hasNext()) {

    String name = iterator.next();

    if (name.equals("B")) {
        iterator.remove();
    }
}
```
Or use removeIf():

names.removeIf(name -> name.equals("B"));

---

# Q125. What is ConcurrentModificationException?

It usually indicates that a collection was structurally modified while being iterated in a way that violates that iterator's rules.

It does NOT necessarily mean multiple threads are involved.

It can happen in a single-threaded program.

---

# Q126. What is an immutable collection?

An immutable collection cannot be structurally modified after creation.

Example:

List<String> names = List.of("John", "Mary");

This throws:

names.add("David");

because List.of() creates an unmodifiable list.

Important distinction:

Unmodifiable/immutable behavior and deep immutability are not always the same thing.

If the elements themselves are mutable, those elements can still change.

# SECTION 18 — ABSTRACT CLASS VS INTERFACE

# Q135. Abstract class vs interface?

Abstract class can have:

- Instance variables
- Constructors
- Abstract methods
- Concrete methods
- Static members
- Protected/private members

Interface can have:

- Abstract methods
- Default methods
- Static methods
- Constants
- Private methods for interface implementation support

A class can:

extend one class

but can:

implement multiple interfaces

# Q136. When would you use an abstract class?

Use an abstract class when related classes share:

- State
- Common implementation
- Constructor logic
- Protected behavior

Example:

```
abstract class Animal {

    protected String name;

    Animal(String name) {
        this.name = name;
    }

    abstract void sound();

    void sleep() {
        System.out.println("Sleeping");
    }
}
```
---

# Q137. When would you use an interface?

Use an interface when you want to define a contract/capability that can be implemented by unrelated classes.

Example:

```
interface Flyable {
    void fly();
}
```
Bird and Aircraft could both implement Flyable despite not sharing a common business hierarchy.

# SECTION 19 — GENERICS

# Q138. What are generics?

Generics provide compile-time type safety.

Without generics:

List list = new ArrayList();

list.add("Java");
list.add(10);

With generics:

List<String> list = new ArrayList<>();

list.add("Java");

list.add(10); // compile-time error

---

# Q139. What is type erasure?

Java generics are primarily implemented through type erasure.

Generic type information is largely removed/translated at runtime for ordinary generic types.

Example:

List<String>

and:

List<Integer>

do not become two completely separate runtime classes.

This is one reason you cannot generally do:

if (obj instanceof List<String>) {
}

because the generic type argument isn't available that way at runtime.

---

# Q140. What is <?>?

<?> is an unbounded wildcard.

Example:

List<?> list;

It means:

A List of some unknown type.

You can safely read elements as Object, but you cannot normally add arbitrary values except null.

---

# Q141. ? extends vs ? super?

This is a very common advanced question.

<? extends T>

Means:

A type that is T or a subtype of T.

Good for reading.

Example:

List<? extends Number> numbers;

You can read Number values.

But you cannot safely add arbitrary Number values.

---

<? super T>

Means:

A type that is T or a supertype of T.

Good for writing T values.

Example:

List<? super Integer> numbers;

You can add Integer values.

---

# Q142. What is PECS?

PECS:

Producer Extends
Consumer Super

If a structure produces values for you:

    ? extends T

If a structure consumes values from you:

    ? super T

Example:

public void printNumbers(
        List<? extends Number> numbers) {

    for (Number n : numbers) {
        System.out.println(n);
    }
}

---

# SECTION 22 — JAVA I/O

# Q148. What is serialization?

Serialization converts an object's state into a representation that can be stored or transmitted.

Java traditionally provides Serializable for Java's built-in object serialization mechanism.

Example:

```
class Employee implements Serializable {

    private Long id;
    private String name;
}
```
However, Java native serialization has security and maintenance concerns and is often avoided for external data formats.

# Q149. What is serialVersionUID?

For Serializable classes, serialVersionUID is a version identifier used during deserialization to check compatibility between serialized data and the current class.

Example:

private static final long serialVersionUID = 1L;

# Q150. What is transient?

transient tells Java's native serialization mechanism not to serialize that field.

Example:

```
class User implements Serializable {

    private String username;

    private transient String password;
}
```
password will not be included in Java's default serialization process.

Important:

transient has specific meaning for Java serialization; it does not universally mean "never store this field anywhere."

# SECTION 23 — COMMON INTERVIEW SCENARIOS

# Q151. Why is HashMap lookup usually O(1)?

Because hashCode() allows HashMap to identify a likely bucket directly rather than scanning every key.

Under normal assumptions, basic get/put operations are expected to be near O(1) average time.

Worst-case behavior depends on collisions and implementation details.

---

# Q152. Why can HashMap performance degrade?

Potential causes include:

- Poor hashCode() implementation
- Excessive hash collisions
- Very high load
- Pathological key distribution

Modern Java HashMap can treeify heavily-collided buckets under certain conditions, improving worst-case behavior for some collision scenarios.

---

# Q153. What makes a good hashCode()?

A good hash function should:

1. Be consistent for an unchanged object.
2. Return the same value for equal objects.
3. Distribute unequal objects reasonably well.
4. Avoid unnecessary collisions.

---

# Q154. What makes a good equals() implementation?

It should:

- Follow the equals contract
- Handle null safely
- Check the appropriate type
- Compare logical identity fields
- Be consistent with hashCode()
- Avoid mutable identity where possible

---

# Q155. What makes a good toString()?

A good toString():

- Is readable
- Contains useful debugging information
- Includes relevant fields
- Avoids secrets
- Avoids huge recursive object graphs
- Avoids expensive operations
